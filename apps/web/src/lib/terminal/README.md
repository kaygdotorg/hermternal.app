# Terminal renderer boundary

`renderer.ts` owns the browser-only Terminal boundary for W-22. It does not import Chat, PTY transport, session coordination, credentials, or live Hermes code.

`current-session-terminal.ts` is the separate current-session bridge. It owns one
`PtyTransport`, exposes one opaque `TerminalBinding`, and maps only the reviewed
lifecycle state into the workspace. It forwards generation-tagged raw
`Uint8Array` views without decoding or retaining them. A renderer-ready gate may
delay the first PTY attach until the lazy TerminalSurface has a mounted sink;
headless coordinator tests leave that gate disabled. TerminalSurface closes the
gate before sink teardown, so a pending attach remains blocked for a later mount
or is rejected by bridge disposal; teardown never resolves readiness, and no
application-level byte buffer repairs a late attach. Workspace ownership
rejection also invalidates the matching stale binding and detaches its PTY;
stale state, notices, and bytes are not hidden while an old binding remains
active.

## Runtime contract

- `createTerminalRenderer()` returns a small `TerminalRenderer` interface with `mount`, `write`, `resize`, `focus`, `whenIdle`, and `dispose`. `whenIdle()` is a renderer-call drain fence only; production W-Term DOM work is confirmed separately with a visible sentinel in browser workloads.
- `createWTermGhosttyAdapter()` is the production adapter. It lazy-loads `@wterm/dom`, `@wterm/ghostty`, the W-Term stylesheet, and the Ghostty WASM only when `mount()` is first called.
- Output stays as raw `Uint8Array` until W-Term/Ghostty receives it. The renderer canonicalizes intrinsic byte views at every public write boundary, rejects spoofed or detached views, checks the intrinsic byte length against the relevant queue cap before making a defensive copy, chunks ready-state writes into cooperative 16 KiB tasks, and keeps both pre-mount and ready-state queues bounded. Queues fail closed when their byte or operation bound is exceeded.
- Ghostty scrollback is bounded to 64 KiB by default and clamped to 1 MiB. The renderer does not keep a transcript mirror, decode output for logging, or expose terminal bytes to diagnostics.
- W-Term supplies native DOM selection and its keyboard copy path. The renderer does not call `navigator.clipboard` or replace browser copy behavior.
- Single-line paste without control characters follows W-Term's normal native paste handling. Multiline or control-character paste is intercepted in the capture phase and requires the supplied `confirmPaste` callback. Confirmation is denied when no callback is supplied, dangerous confirmations are serialized in event order, oversized dangerous payloads are rejected before queueing, and active plus queued confirmations share one bounded aggregate byte cap and count limit. Callback/backend failures are caught, and accounting is released on resolve, reject, cancellation, remount, and disposal. Accepted paste uses W-Term's bracketed-paste mode and strips escape bytes before sending.
- WASM, module, and adapter failures render one accessible `role="alert"` state with stable copy. Raw exception text is not shown or logged. The error keeps ownership of its host until `dispose()` or a remount, so stale loading/error DOM and W-Term classes are removed deterministically at the boundary.
- `dispose()` is idempotent and safe during an in-flight lazy load. In-flight mounts are invalidated without awaiting an unsettled promise, so dispose/remount can proceed. Mounting a new renderer over an existing host explicitly disposes the previous owner before taking ownership. If the terminal was focused before a safe remount, focus is restored after the new W-Term instance is ready. Dangerous-paste approval captures the mount generation, host, and backend identity before awaiting confirmation, so an old approval cannot write to a remounted terminal. A stale async backend uses a host-preserving disposal path, removes only its known nodes/listeners, and restores every known W-Term-mutated class to its exact pre-mount presence when that generation still owns the observed state; released or reused owner values are never cleared.
- With `autoResize: false`, the adapter re-locks the host height after explicit resizes using the rendered row height, preventing a larger row count from being clipped by W-Term's initial height lock. Renderer and adapter resize calls reject dimensions outside the reviewed 1–2000 column and 1–1000 row bounds.

The adapter lazy-loads `terminal.css` with the W-Term stylesheet, so selecting Terminal does not add terminal CSS to the initial shell. It uses the shared `--font-mono` token when present and falls back to Geist Mono plus a system monospace stack for this isolated scaffold. The current W-01 shell does not yet define `--font-mono`; adding that global token belongs to the shared design-token work, not this renderer boundary.

## Accessibility boundary

The host is a labelled `region`; W-Term keeps native selection and a keyboard input for focus. Pinned `@wterm/dom@0.3.2` creates that textarea with `aria-hidden="true"` and `tabindex="0"`, which violates `aria-hidden-focus`. The production adapter removes the invalid hidden state and adds the stable accessible name `Terminal input` immediately after `WTerm.init()`. The production-shaped Playwright axe test covers the normalized DOM, and the unit adapter test covers the exact pinned input attributes. This is a compatibility adaptation, not a claim that upstream 0.3.2 has fixed the issue.

The renderer verifies keyboard focus, native selection, copy event pass-through, screen-reader labelling, reduced-motion cursor behavior, and the normalized W-Term input in the local prototype. Broader 200% zoom, forced-colors, and reduced-transparency checks belong to the surrounding shell accessibility suite; this boundary does not synthesize live cursor announcements or semantic command history.

## Pinned W-Term lifecycle limitation

`@wterm/dom@0.3.2` exposes `WTerm.destroy()` but neither it nor `@wterm/ghostty@0.3.2` exposes a deterministic Ghostty core or WASM release method. The adapter destroys W-Term's DOM/listeners and drops the active bridge reference in `dispose()`. If a stale async mount resolves after ownership changes, it removes only that stale instance's known nodes/listeners and never calls the upstream `innerHTML = ""` teardown against a reused host. The renderer also bounds pending output and Ghostty scrollback. It does not claim deterministic WASM release. The safe options are: (A) locally patch/vendor W-Term, which is the fastest way to add release and accessibility fixes but expands dependency review and maintenance; (B) keep one renderer/core alive per page and hide/show it until page teardown, which avoids repeated initialization but conflicts with independent remount ownership and retains memory; or (C) move to a newer reviewed W-Term release if it supplies both fixes, which is the safest long-term option but requires API, bundle, and regression review. For this pinned prototype, the adapter-level accessibility normalization plus host-preserving best-effort disposal is the smallest safe change; a dependency upgrade remains the preferred follow-up when an audited release exists.

## Tests and workload

`renderer.test.ts` uses an injected renderer adapter with deterministic synthetic terminal state. It proves lazy initialization, ordered raw-byte delivery (including split UTF-8, combining marks, wide graphemes, ANSI, cursor, and alternate-screen workload fixtures), resize bounds, cooperative ready-state output, loading persistence, unresolved-mount cancellation, native selection/copy pass-through, serialized paste confirmation and failure guards, remount/dispose ownership, controlled initialization failure, bounded pending output, typed-array canonicalization, benchmark distribution recomputation, checked-in evidence validation, and the absence of byte logging. The production adapter tests cover the pinned W-Term input shape, accessibility normalization, bracketed paste, height relocking, direct public-boundary validation, idempotent disposal, and preservation of preexisting host values. No test starts Hermes or a PTY transport.

`../../../tests/bench/terminal-renderer.bench.ts` is a local-only Playwright workload harness. Run it with an explicit clean checkout revision, `GIT_COMMIT=$(git rev-parse HEAD) bun run benchmark:terminal`, to emit raw samples and p50/p95/p99 distributions for cold mount, first glyph, sustained output, resize, 1 MiB replay, and repeated mount/dispose. It rejects missing or malformed commit input and dirty execution-critical renderer, dependency, and benchmark files, validates per-workload sample counts, recomputes every distribution field from the rounded raw samples, and records SHA-256 digests for those source, package manifest, lockfile, and harness inputs. Before page load it installs a Playwright request route that allows only the benchmark loopback origin plus browser-internal `data:`, `blob:`, and `about:` resources; disallowed requests are aborted, counted, and fail the run. The evidence records `disallowed_network_requests: "0"`, and the validator requires that value. The renderer unit suite independently parses and validates the checked-in evidence trace, including its schema, exact source/input relationship, workload set, repetition metadata, recomputed distributions, visible `render_fence: "visible-text-sentinel"` metadata, browser environment, long-task samples, memory support/field relationships, workload dimensions, every emitted build artifact path/size/SHA-256 entry, and recomputed entry/chunk/WASM/CSS totals against a fresh build of the exact reviewed source commit. It also records the production client chunk and emitted Ghostty WASM sizes and SHA-256 values, main-thread long-task entries, and heap samples when Chromium exposes `performance.memory`. The checked-in evidence head may differ from the benchmark source only through the evidence JSON path. The checked-in `../../../tests/bench/terminal-renderer.evidence.json` records the exact renderer source commit used for its synthetic trace; the evidence commit may be one commit later because the trace is itself checked in. Later runs are expected to vary. The first cold-initialization sample includes the lazy module/WASM fetch and later samples show warm repeated initialization. Measurements are evidence only; no approved performance budget is asserted, so multi-second tail and long-task observations remain explicit residual performance risk. The benchmark workload is synthetic and never starts Hermes or PTY transport. Because pinned Ghostty has no deterministic release API, post-dispose heap readings are observational rather than proof of core/WASM reclamation. The long-run browser stress fixture uses ASCII plus ANSI to avoid a known pinned-Ghostty grapheme-page integrity trap; Unicode, combining-mark, and wide-grapheme behavior remains covered by the renderer unit workload.
