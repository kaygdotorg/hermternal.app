# Live workspace boundary

`LiveWorkspaceSession` coordinates the reviewed browser transports for one authenticated Hermes session.

## Ownership

- REST remains the source of truth for the session list and completed message history.
- The controller replaces presentation arrays after each server read. It does not keep a secondary transcript store.
- One JSON-RPC transport belongs to one selected session. A session change closes that transport before creating another one.
- Generation numbers and abort signals prevent stale session reads from publishing after a newer selection.
- Approval and clarification replies capture their generation, transport identity, and pending-map owner. A late completion or failure cannot mutate a replacement chat, disposed workspace, or newer interactive item.
- `invalidate()` first revokes Chat and Terminal publication ownership, then closes transports, aborts reads, and removes session and timeline references before subscribers receive the signed-out view. `dispose()` marks the workspace closed and clears subscribers before close callbacks can re-enter. The route root owns final disposal: an authenticated view borrows its injected workspace, so expiry may unmount and later remount that view without closing the reusable root session. Route teardown alone permanently disposes Chat, PTY, coordinator subscriptions, and sockets, and it is idempotent.

## Current-session Terminal prototype

The live workspace composes one current-session Terminal bridge beside Chat. Switching modes reuses the selected durable Hermes session. A newly created draft remains Chat-only until its first turn completes and the following REST read confirms durable promotion; only then may the Terminal coordinator bind to that session. Terminal does not create a session, replace the Chat transport, or act as a second workspace. The renderer-ready gate owns the first PTY attachment: the bridge does not attach until the mounted `TerminalSurface` reports that its lazy renderer is ready. Returning to Chat hides the terminal presentation without discarding the current-session owner. The runtime handoff first removes Terminal's painted hit-test layer, then releases and focuses the Chat target; desktop Chat controls are under that layer, so a layout rect alone is not adequate visibility evidence. Narrow selectors follow the same ordering even though they are stacked above Terminal.

Detach and close are presentation lifecycle states, not transcript events. Session replacement invalidates the old Terminal owner before the replacement becomes visible. A later adapter completion or event from that old owner cannot publish into the replacement. Authenticated-view remounts reuse the root-owned workspace, while final root disposal releases Chat, Terminal, renderer readiness, subscriptions, and adapter resources exactly once. Adapter construction and attachment failures remain fail closed and expose only bounded, sanitized lifecycle state. A latched PTY construction failure on an unpromoted fresh draft leaves both Terminal controls natively disabled with their existing explanation; it neither enables a silent mode request nor renders a failure surface. Only a coordinator-confirmed durable session may present that bounded failure as an accessible alert with a Return to Chat escape; no thrown text enters the UI. Once latched, that sanitized setup failure remains observable through authentication expiry and authenticated-view remounts until a replacement owner or final root disposal clears it.

This work is a prototype contract verified with deterministic adapters and synthetic browser boundaries. It does not prove a live Hermes PTY integration. Read-only Paper inspection confirmed that the approved “Terminal narrow and mobile” light and dark Chat–Terminal selector states were used; this correction makes no Paper design edit or intentional redesign. Runtime ownership, readiness, stale-event, and cleanup behavior remains verified in the local mocked prototype. The root now receives a bridge-issued opaque callback stamp before a terminal state can retire its binding. A module-private producer registry resolves that stamp to the actual binding and native generation, so caller-created lookalikes cannot mint a root lease. The root records an opaque object capability for that exact bridge lifecycle and retires it on replacement, authentication invalidation, or route teardown. A close callback retains its captured stamp even after the bridge binding retires, allowing only the already accepted lease to expire once; a callback from the prior authenticated lifecycle is ignored, while a newly registered bridge lifecycle remains eligible.

The workspace snapshot retains no terminal bytes, terminal transcript, WebSocket ticket, credential, or provider secret. Raw `Uint8Array` output passes only to the mounted renderer subscriber. Tests use opaque placeholder identities and never assert or persist ticket values or terminal content.

## Prompt delivery

A prompt is submitted only after REST restoration and the explicit JSON-RPC connection and `session.resume` sequence complete. Streaming text is transient presentation data. Official Hermes may omit `request_id` from delta and completion events; the JSON-RPC transport exposes its fail-closed sole-operation correlation as the public request ID before this controller applies prompt ownership. A successful completion triggers a new REST message read so server-owned history replaces it. While a prompt owns completion reconciliation, a synchronous subscriber cannot send another prompt: the controller rejects it before the transport boundary. The post-call ownership check remains necessary for callbacks that originate inside the transport call itself. The prompt allocates its refresh epoch only after the synchronous transport call returns; completion and failure continuations consume that exact owner instead of minting a new one from a promise reaction. That read receives the prompt operation's abort signal, so invalidation, session replacement, logout, and disposal cancel it and stale authenticated data cannot repopulate the timeline.

The live Hermes gateway does not provide one total order for REST, JSON-RPC replies, events, and socket lifecycle callbacks. The earlier synthetic fixture assumed a request acknowledgement preceded prompt events; official Hermes can start prompt work and emit completion-related events before returning that acknowledgement. A generic failed or uncertain callback can also arrive after a successful completion and its REST read. During restore, the bounded REST projection is provisional and may be visible before chat factory, ticket, connection, or `session.resume` succeeds. The workspace commits a general history barrier after every successful REST replacement. For an exact prompt that observed a successful `message.complete`, it defers a matching generic `failed` callback while that prompt's REST reconciliation is pending and suppresses the callback after the reconciliation commits. A refresh failure, cancellation, or ownership loss revokes the pending completion and leaves the correct recovery or replacement state. Initial restore and reconnect history do not establish completion ownership, so their generic failures remain `retryable-error`; a real `delivery_uncertain` callback still publishes `retryable-error`, and classified authentication/origin closes remain permanent. If history loading fails before `openSession()` can publish the selected identity, the workspace keeps only that opaque persisted session ID as private retry ownership; Retry reopens that same server session and never falls through to `createSession()`. Once bounded history is mapped and published, the normal active-session retry path takes over. If the factory fails before a chat exists, Retry starts a fresh active-session lookup, factory, ticket, connection, and resume operation with generation ownership; a new-session factory failure without a stored ID retries the guarded create path instead. Stale or reentrant retries cannot adopt a replacement. Authentication-required and incompatible-origin classifications always bypass this generic barrier.

Hermternal never reconnects or replays a prompt automatically. An uncertain delivery shows a fixed warning. The user must reconnect and inspect Hermes history before deciding whether to send again.

## Bounded presentation

The controller reads only documented text keys from known JSON-RPC events. Unknown payload values stay opaque. Compact tool rows show a name and fixed status copy, never tool arguments or raw output. REST mapping excludes system context and session preview transcript text.

`WorkspacePreview` defaults to deterministic fixture copy. Live callers must pass `dataMode="live"`, explicit timeline data, and disable the fixture-only artifact inspector. The live empty and recovery copy does not claim that controls are mocked or that an unretained draft is safe.

Authentication, provider discovery, REST, WebSocket tickets, and JSON-RPC remain separate reviewed boundaries. This module composes them; it does not weaken their same-origin, cancellation, size, or diagnostic rules. A genuine REST `LiveRestError('unauthenticated', 401)`, ticket HTTP `401`, `JsonRpcChatError('authentication-required')`, or active close `4401` remains `permanent-error` and may expire the authenticated root; REST `403`, ticket `403`, and close `4403` remain outside that sign-in boundary. Generic connection failures remain `retryable-error`. The workspace retains the terminal reason and close classification separately from that broad state: an active prompt after `4401` shows sign-in guidance, while `4403` shows incompatible-origin guidance. The rendered authentication-required actions call the root-provided auth recovery bridge, which invokes `BrowserAuthSession.expire()` and invalidates local workspace state; incompatible-origin actions stay on the fail-closed boundary. Reconnect recovery exposes working `Check connection` and `Cancel` actions: the former starts the guarded retry owner and the latter aborts it without replaying a prompt. Uncertain-delivery callbacks and prompt-failure cleanup cannot downgrade either permanent result.

The pre-identity retry regression deliberately fails the first history read, defers the second, and drives the real browser transport through ticket acquisition, `gateway.ready`, and `session.resume`. It keeps the session ID opaque in the ownership trace while asserting that detail lookup, both history reads, selected-session transport setup, and resume all address the same server session; the socket sends no `session.create`. The test-local trace records only generation, controller identity, abort, disposal, and gate results. This boundary is why the two fail-closed ownership gates remain unchanged until a live reproduction supplies a false predicate or an abort transition; production code does not log IDs, tickets, transcript data, or response bodies.

The page routes Chat authentication failures through the existing no-argument `BrowserAuthSession.expire()` boundary. Terminal `4401` actions instead forward the exact root lease returned for a bridge-issued callback stamp to `expireTerminalAuthentication()`. Root ownership makes expiry safe for authenticated-view remounts and rejects forged, retired, or replacement-terminal callbacks. The root owns final disposal; stale callbacks after route teardown are ignored.
